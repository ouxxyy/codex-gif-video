# 人物一致性测试流程

1. 使用用户主参考，或用允许的2.6模型生成一张中性、全身、无遮挡的角色图，保存脸型、发型、眼镜/配件、服装、配色、头身比及其 hash。
2. 同一风格生成至少两个不同动作，分别附同一个主参考。先检查各帧，再比较跨素材特征；不能只看首帧或只凭衣服同色判断。
3. 若任务需要换风格，另作一段控制样本，仅改变指定材质、线稿、背景；身份与锁定配色不应跟着换。它与同风格测试分别判定。
4. 完整解码所有帧并做带编号/时刻的接触表，必要时补脸部裁切；原 GIF 保持字节不变。静态检查不证明正常速度运动自然度。
5. 分项记录 face/hair/eyewear、服装款式、锁定颜色、体型、肢体结构、同片帧间稳定性及动作语义。任一关键身份特征失败即不合格，不用综合高分掩盖。
6. 结合独立复核；Jev 超时保持 error/unknown，不称通过。修改后核对新文件，旧结果保留。仅对已观察到的具体缺陷做有额度的定向修正。

API 主参考命令：

```bash
python3 <skill>/scripts/official_api.py reference --prompt-file character.txt --out profiles/hero.png --budget-file evidence/generation-budget.json --env-file .env.local
```

它只生成静态参考 PNG，不拼装动画，计入 reference 额度。返回图片需实际查看；命令成功不代表角色设计已获视觉通过。目录中的 nora-master.png 是虚构测试角色，可作为例子，不代表用户必须沿用该角色。
