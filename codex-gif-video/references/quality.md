# 验收与探索

## 质量门槛

技术检查仅判断 GIF 原字节、帧数、帧延时、解码、帧间像素差异、实际尺寸/比例。像素变化可能只是闪烁，不能推断运动自然。所有测试合成 GIF 都只用于验证文件处理，不是生成效果样本。

每个素材分别检查：

1. identity：人物/物体身份稳定；跨批次对照主参考。
2. style：材质、配色、比例、光照稳定。
3. structure：无多余/消失肢体、变形道具、错误遮挡或画面裁切。
4. motion：正常速度完整播放，重心、加速、停顿、动作方向自然，无明显跳变、重复姿势或闪烁。
5. semantics：初始状态、动作、结果准确对应口播，不能只是装饰性动画。
6. loop：seamless 检查循环接缝；once 检查动作完成态，允许非循环，不要求强行回到起点。

7. clean_visual：逐帧确认无字幕、标题、文字标签、水印或其他叠加层；这不能仅靠 ffprobe 判断。

未知项保持 unknown。任一 fail/unknown、缺完整播放、缺全帧检查、技术失败、来源证据不足均不能 ready。对当前原文件/参考/口播进行独立复核，不用历史结果覆盖修改后的文件。

审阅 JSON 示例（这是格式示例，不能直接当成真实检查）：

```json
{
  "asset_sha256": "实际哈希",
  "reviewer": "实际复核者或工具",
  "full_playback_observed": false,
  "all_frames_observed": false,
  "checks": {"identity":"unknown","style":"unknown","structure":"unknown","motion":"unknown","semantics":"unknown","loop":"unknown","clean_visual":"unknown"},
  "evidence_files": ["实际原始检查记录.txt"],
  "notes": "注明实际观察范围与缺陷"
}
```

接触表/抽帧可帮助结构检查，不能替代完整播放。Jev 静态视觉复核若不能检查完整动态，motion 与 full_playback 保留未知，另由可播放原 GIF 的实际观看补齐。review 命令记录声明并验证文件绑定，不能认证人的感知；不得生成伪造通过记录。

## 首轮实验配额

共用一份预算：8 次 GIF、3 次参考图，原生工具失败/超时也计入。当前入口失败时停止，不擅自切入口；用户已授权官方 API 时按其选择执行。配额是上限，不要求花完。

- E0：1 次入口探针；真实文件与来源证据可核验后才能继续。
- E1：状态变化解释“任务越堆越多，人开始手忙脚乱”。
- E2：同一主参考下的另一动作，和 E1 比较身份。
- E3：E2 末帧作起点，再附主参考，生成下一段原生 GIF；只提取参考，不重编码动画。
- E4：相同动作加入明确预备、重心与收势要求，与已有基线比较。
- E5：生成“逐步卸下负担”，与 E1 做语义对照；避免把原文标签当作理解依据。
- E6–E7：按上述最重要失败做最多两次对照/复测，不为了刷高分反复抽样。

每条记录必要条件、原始提示、参考、结果、耗时/可获得用量、缺陷和结论。只有一两个样本不能推算成功率。

如 E0 被账户权限、模型证据缺口或工具能力阻塞：停止真实实验，保存诊断与待执行请求，完成接口/离线测试；报告未验收，不擅自切入口、更换模型或降低质量门槛。用户随后明确授权其他允许入口时作为新尝试保存，旧失败结果不改写。

## 官方来源与待审片

model_evidence与official_request_evidence分开：API无顶层model不自动等于来源失败；新官方请求可按固定端点、显式模型、request ID与哈希核验。历史unverified不改写。感知检查规则保持：全帧静态不等于正常速度完整播放。需要先供用户观看时，compose_movie.py --review-copy可生成rendered_pending_review，技术/比例/时长/来源仍须通过，审阅未知项随回执交付。该MP4不能被宣称为ready或全面验收通过。
